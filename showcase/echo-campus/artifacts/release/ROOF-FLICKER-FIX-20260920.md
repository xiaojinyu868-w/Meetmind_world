# 园区屋面闪烁修复与验证

2026-09-20；范围仅 Echo Campus 独立展示站。

## 复现与成因

用户框出的 C 地块白色屋面在镜头旋转时出现灰黑条纹。生产站以相机 `[135,102,361]`、目标 `[246,42,224]`、FOV32 可稳定复现。关闭全部阴影以及改用无光照材质后，条纹仍在；分别给网格着色证明是不同网格抢占深度。

射线点 `[253.50705,39.499805,220.62602]` 同时命中 C 原始文件的“石膏”和“石材幕墙”，高度与法线相同。独立源几何检查确认共面早于 Draco 压缩，不是整栋园区组装坐标错误。另有金属屋顶粗条带在关闭阴影后消失，属于远景阴影自身遮挡问题。

## 修复

- 新增 `VenueSurfaceDepth.js`，仅匹配已审计的 `sourceVenue + material.name`：C 商业原文件“石材幕墙”深度偏移(-1,-4)，T6 原文件“beton3”基底(+1,+4)。保留独占立面，深度测试、几何、颜色、纹理与可见性不变。材料克隆缓存并在原导入器释放前恢复/销毁，避免污染共享资产。
- 完整园区的 source/event 两种视图都应用该已知表面修正；其他导入及自建场景不受规则影响。
- 新增 `EventShadowTuning.js`，远景按阴影像素的世界跨度和太阳倾角计算深度补偿，PCF radius从3调至.75。远景 normalBias设0，避免双面屋顶向下法线将采样推入模型。当前1024覆盖下bias约-.001216。近景人物接触阴影维持原值。
- 完整 GLB 未改动，SHA256 仍为 `78bbf162e6a3ce8ac17294bf1ca649976cbba536687f90e7598ce4c8c4ee4092`。不删建筑、不改模型位置、不改相机近裁切面。

## 验证结果

- `npm test` 167/167通过；生产构建和diff检查通过。新增白名单、共享材质隔离、纹理/几何保持、幂等清理、阴影参数缩放与视图恢复测试。
- 独立 Playwright 浏览器在真实 HTTPS 展示站录制相同12帧轨道的修复前后对照。该 C 屋顶原有深浅跳变条纹在已验收轨道中消失。另实测拖动与滚轮缩放、反面镜头、远近镜头及主要建筑区域。
- 固定世界坐标屋面小块 X253..254/Y39.5/Z220..221 经相机重投影采样：12帧平均帧间灰度差从61.80降至0.10（0–255）。此指标仅覆盖该问题小块，不能代表全园所有表面。
- 已复查source/event往返、T6活动入口、人物近景，近景阴影参数仍为bias=-.00006、normalBias=.025、radius=3。
- 桌面1440×900与触控模拟390×844通过，页面错误和失败请求为0。移动视口模拟不等于手机实机验证。
- 截图、轨道录屏及JSON证据见同目录 `roof-flicker/`。`before-after.png`为同相机真实网页对照。
