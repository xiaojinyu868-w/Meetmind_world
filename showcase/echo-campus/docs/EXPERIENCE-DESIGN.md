# 相遇之庭 · 体验设计与实现说明

**版本**：v1.1 · 2026-10-02 · To B 合作线
**一句话**：手机碰一下手环或立牌，一秒拿到一个属于你的分身，走进活动现场的数字庭院；看见彼此、打个招呼，双方确认后才点亮相遇、交换微信。

## 1. 这个产品要解决什么

线下活动（本轮面向支付宝「碰一下」与江苏投资人活动的合作）有三个老问题：

1. **入场太重**：扫码后先填一长串表单，来宾直接流失。
2. **认人太难**：几百人的现场，不知道谁是谁、该先认识谁。
3. **相遇留不住**：聊得不错，散场就断了；直接要微信又显得唐突。

相遇之庭的设计取向：

- **零门槛进入**：碰一下即进，不采集任何资料，不要求上传照片。分身从预设形象里分配，人人不同、彼此可辨。
- **轻社交而非强社交**：先看见，再打招呼；招呼可以带一句话；对方可以接受，也可以「先不了」（发起方不会收到拒绝提醒）。
- **双向确认才交换**：微信（或任意联系方式）默认「相遇后可见」，只有双方都确认相遇后才对彼此显示，公共世界和大屏永远看不到。
- **现场有仪式感**：大屏是活动的公共舞台，每位来客「以光的形式」抵达，每次相遇在世界里点亮一条金色连线。

这套东西是可复用的底座：换一份活动配置（名称、主题色、分身阵容、身份类别、打卡点、标签表）和一个场景，就是下一场合作活动。

## 2. 三个角色、三块屏

| 角色 | 入口 | 看到什么 |
| --- | --- | --- |

## 3. 来宾旅程（手机）

### 3.1 碰一下 → 入场仪式（不等 3D）

- 页面先出深色入场层（DOM，不依赖 3D 资源），同时后台加载场景与活动连接。
- 顶部「已感应到你的到来」+ NFC 涟漪；手环标签会显示「已识别投资人手环」。
- 中间是**分身卡**：全身形象、代号（如「朱砂」）、英文名、气质词（灵感）、特征（红色贝雷帽 · 芥末黄开衫）、「即将成为第 017 位来客」。
- 主按钮「以「朱砂」进入」，次按钮「换一个形象」。下方一行说明：进入即同意以分身出现在公共世界；不采集照片、手机号、定位；名片和微信自愿填写，可随时隐身或删除。
- 点「进入」后：编号盖章动画 → 入场层淡出 → 镜头从庭院上空俯冲到你的分身 → 分身在光柱中出现并挥手 → 「欢迎，朱砂·017」。
- 如果 3D 还没加载完，进入动作照常完成，场景就绪后自动补播降落镜头。

分配规则：服务端在当前活动开放的分身里选**使用最少**的一款（同数时按身份 ID 哈希），保证人群里形象尽量分散；来宾也可以主动换。默认名为「代号·编号」，填写昵称后显示昵称。

### 3.2 庭院里

- 顶部：活动名 + 实时人数/相遇数；右侧「我的相遇」（有待确认时红点）与「相遇护照」。
- 底部：「我的名片」（自己的头像与编号）+「认识新朋友」。
- 世界里每个人头顶有名字牌，自己是深色「你 · 名字」；有人向你打招呼时，TA 的名字牌带一个小心形。名字牌只显示离镜头最近、互不重叠的若干个；镜头框住某个人（名片、入场特写）时，别人的名字牌不会压在 TA 身上。
- 站位：庭院按六边形网格排出三人一组的交谈小圈，避开树池、长椅、指示牌和两对演示交谈，从中心向外依次落位。来宾按入场编号取位，所有设备算出的位置一致，任何两人间距 ≥ 0.95 米；坐满时多出的人暂不出现，而不是叠在一起（`src/runtime/SocialFloor.js`）。
- 只有快照里新出现的人才播放抵达光柱与提示音；首屏陆续加载出来的分身静默出现。

### 3.3 名片（点人物）

手机上是底部抽屉（约 2/3 屏），镜头自动把对方的上半身框在抽屉上方；电脑上是右侧浮卡。

- 色带：编号 + 气质词 + 形象特征（用分身主色）。
- 头像外圈 = 手环颜色（身份类别）。
- 「TA 能提供 / TA 想认识」以标签显示；「你们的交集」由双方公开的供需算出（如「TA 能提供你在找的『融资』」）。
- 动作随状态变化：
  - 未相遇：「想认识 TA」→ 展开招呼（四个预设句 + 自定义一句，可不填）→「发送招呼」。
  - 已发出：「已打招呼，等待对方确认」。
  - 收到：显示对方的那句话，「接受，交换名片」或「先不了」。
  - 已相遇：「你们已在相遇之庭相遇 · 已确认」+ 对方的微信（一键复制）。
- 演示人物会标注「演示人物不会真实回应」。

### 3.4 我的名片（全部选填）

分身卡 +「换个形象」（12 款网格选择，草稿不丢）；昵称、一句话介绍、身份、机构；活动身份（手环颜色）；我能提供 / 我想认识（一键标签 + 自由补充）；微信与可见范围（相遇后可见〔推荐〕/ 所有人可见 / 不展示）；「在庭院中显示我」（关闭即隐身）；显式勾选同意后保存；底部「删除我在本活动的全部资料」（二次确认）。

### 3.5 认识新朋友

- 资料为空时，直接给出可勾选的方向标签（勾选同意后才公开到名片），一步得到推荐。
- 推荐卡展示理由，展开可核对双方原文（固定词表匹配，不使用大模型）。
- 下方「庭院里的人」网格，点头像即打开名片、镜头飞过去。

### 3.6 相遇护照

圆环进度 + 已盖章数，点位以印章样式呈现。现场用手机碰点位立牌（`?tag=CP-future`）即盖章并跳到对应印章；重复触碰不重复计分。演示环境保留「演示盖章」按钮。

合作方控制台的「NFC / 双端体验」面板末尾有**现场标签清单**：入场闸口 `GATE`、每类手环 `WB-<类别>-0001`、每个点位 `CP-<点位>`，每条可复制链接或切成二维码，用于写 NFC 标签与彩排；清单按活动配置自动生成。正式活动开启签名后，静态链接会被拒绝，由碰一下适配层附加签名（见 `TAP-ADAPTER.md`）。

## 4. 大屏

- 左上：活动名（衬线大字）、副标题、实时人数与相遇数。
- 右侧：「刚刚抵达」（头像、名字、代号与气质）与「刚刚相遇」（两人头像 + 心形）。
- 左下：碰一下 / 扫码入场卡（二维码自动指向当前场景的入场链接）。
- 世界：镜头在庭院南侧开阔面做钟摆式环拍（避开主楼与坡地遮挡），所有已确认连线常亮并流动，新相遇有一次金色脉冲、两位当事人的分身同时鼓掌。

- 主题色由活动配置下发（见 `EVENT-PROFILE.md`），无需改代码。
- 尊重「减少动态效果」系统设置：关闭卡片翻转、光柱与环拍。

### 5.1 庭院布置（活动视图）

只依据标定好的活动边界生成，纯视觉、不参与碰撞与点选（`src/scenes/CourtDressing.js`）：

- **铺装**：1.2 × 0.6 米暖砂岩错缝铺装，边缘柔和融入原有地面（近侧在南入口抬高平台之前收边，避免平台像地面上的破洞）；取代原先的浅灰石材层。
- **地面徽记**：庭院中心的铜色字带圆环，环上文字取自活动配置的「名称 · 品牌 · 副标题」，中心是两圆相交的「相遇」标记；换一场活动自动重绘。线条按来宾镜头约 16° 的俯角加粗，斜看也读得出来。
- **串灯天幕**：灯杆立在庭院北沿与南侧两个外角（在来宾默认镜头之外），灯串沿北沿一排、再从北沿扇形拉向两角，中间两根在人群上方交叉；灯泡带呼吸光晕。
- **旗帜**：两面深绿竖旗挂在最靠中轴的两根北沿灯杆上，正对来宾，写活动名。
- **光线与胶片**：见 5.2。

实现备注（排查渲染问题前先读）：three r185 在反向深度缓冲下会把排序后的渲染列表整体反转（`renderOrder` 跟着反向），并把 `AlwaysDepth` 映射成 `NeverDepth`；园区地面材质带 `polygonOffsetFactor -2`，在 16° 俯角下会把地面往镜头拉近十几厘米，压住几厘米高的地面效果。布置层因此按深度模式取 `renderOrder` 和「总是通过」的深度函数：先画园区地面，再由铺装与徽记无条件覆盖并写入真实深度，人物、接触阴影、抵达光环随后都对着铺装深度测试——这也让原本在来宾视角下被地面吃掉的接触阴影和光环重新可见。

### 5.2 光与胶片（美术底座）

数字都在 `src/runtime/CourtLook.js`，场景里不另写一套；活动视图开启时由 `CourtDressing` 铺上，切回源模型即恢复（胶片回到恒等的 `neutral`）。

- **光（16:26 侧逆光）**：太阳在来宾背后的前方、偏离到场镜头视线 45°（`venue-campus.json` 的 `eventLook.sun`：方位 135°、仰角 30°；四周高楼，低于 30° 时庭院地面大半落进楼影），`#FFC48A` 3.2，影子拖向镜头；天光 `#B5C9EC / #E4C29C` 0.95；冷色补光 0.3 从镜头一侧（太阳的水平镜像，仰角 35°）打在逆光留下的阴面上——再强画面就发平发灰。曝光 1.03。场地可在清单里改太阳；调试时 `?debug&sun=方位,仰角` 不改文件试光。
- **胶片（收尾着色器，作用在显示值上）**：饱和 1.12、自然饱和 0.22、对比 1.04、暖 0.035、暗角 0.24、颗粒 0.028、暗部向梅灰 `#3E3546` 提亮 0.8；泛光只给亮过 1.4 的灯泡与高光（手机不开泛光）。校园是浅色石材与玻璃，所以胶片是加色加反差，而不是像人生广场那样压。暗角与调色都在 WebGL 里，不再叠 CSS 滤镜或遮罩。
- **镜头景深带**：行走（到场、庭院）轻微移轴 0.1；大屏 0.35 的微缩感；点开人物是特写，焦点对准人物所在的屏幕高度（手机在名片上方），背景虚化，并额外提亮暗部 2.0——逆光下的深色外套不能死黑。竖屏到场镜头抬高到约 25° 俯角，雨棚只占顶部一条。
- **录像带印记**：来宾入场的那一刻打出 `PLAY ▶ / PM 5:42  OCT. 08 2026 / 相遇之庭  NO.016`；自己参与的相遇被双方确认时打出 `REC ● / 时间 / 我 × TA`。1.6 秒后淡出，不接收点击；大屏不打。

分身只代表「样子」，不代表身份；身份由来宾自己的类别（手环色）与名片决定。

- **特写高清**：人群里用 1K 颜色 + 512 法线的轻量模型；镜头框住某个人（名片、入场特写）时，按需换上这款形象的 2K 颜色、1K 法线与 1K 粗糙度贴图（每款约 0.25–0.6 MB，后台线程解码），同款的所有人一起变清晰。常驻上限手机 3 款、电脑 6 款，超出时最久没看的退回 1K；自己的分身始终保持高清。
- **站姿**：Tripo 的待机动作双臂外张像橱窗模特，待机时上臂向身体收拢约 6°，挥手、交谈、鼓掌时平滑淡出，动作本身不受影响。
- 头像与全身像用同一套高清贴图和站姿渲染。

### 6.1 脸：眨眼、表情、口型

Tripo 人物没有脸部骨骼和 blendshape，眼睛和嘴是画在贴图上的。`src/runtime/TripoFace.js`（取自借光 `school/src/kit/tripoFace.js` @4de5344，加了两处：每款形象可设皮肤色差阈值；同款形象共用正面照与轮廓纹理）先把头部正面投影成一张「正面照」，在里面找到画出来的一对眼睛和嘴；眨眼、笑眼、张嘴都在片元着色器里按脸平面坐标重画，顶点一个不动，所以不会撕裂，中性时一个像素都不改。

- **节奏**：每 2–6 s 眨一次（约六分之一连眨两下），每次约 0.13 s；名片打开、对方挥手打招呼时眼睛带笑，并有一闪惊讶；双方确认后鼓掌时笑出声（嘴每秒开合约 3 次）；演示人物轮到说话时，嘴按无声的音节动（每秒 4–5 个，3–7 个一串，串间换气 0.25–0.6 s），听的一方合着嘴。每位来宾的眨眼节奏由座次种子决定，几块屏上一致。
- **逐款核对**（`src/runtime/CharacterFace.js` 的 `FACE_SUPPORT`；每款都看过闭眼、半闭、笑眼、aa / oh / ee 和 3/4 侧面的闭眼）：

| 结果 | 形象 |
| --- | --- |
| 眨眼 + 表情 + 口型 | 珊瑚、晴跑、霜叶、赭石、白噪、青瓷、沙洲、青柳（皮肤阈值 20） |
| 只有口型 | 朱砂（齐刘海压在眼睛上，眼睑会取到头发色）、小满（粗黑框会被扯变形）、墨川（同上；皮肤阈值 24） |
| 保持不动 | 松石（胡须盖住了嘴，找不到） |

  新形象默认不动，核对过再登记。识别本身也会失败（找不到一对眼睛或嘴时），失败就保持原样。
- **时机与开销**：识别模块（gzip 约 17 kB）在第一次找脸时才加载；每款形象只识别一次（读贴图像素 + 四步，每步占一个空闲回调，单款主线程合计 24–79 ms），同一时间只做一款；带脸的着色器先用 `compileAsync` 编译好再换上。电脑与大屏在形象加载后就找；手机只给被框住的人（名片、入场特写）找。
- **材质**：每位来宾一份材质（眨眼各自独立），同款共用正面照与轮廓纹理；特写高清贴图换到共享材质上时，每帧跟过去。眨眼或说话的那一刻，眼睛和嘴这一小块取自识别时的正面照（来自 1K 贴图），其余部位始终是当前贴图。
- **QA**：`?debug` 下 `__ECHO_CAMPUS__.face(id, { blinkLeft: 1, blinkRight: 1 })` 定格表情，`face(id, null)` 恢复节奏；`__THREE_GAME_DIAGNOSTICS__().faces` 看每款的识别结果、耗时和已装上的人数。

## 7. 性能与加载

- 手机来宾默认加载**庭院裁切版**场景 `venue-campus-court.glb`（主入口 90 米内全部三角面，gzip 约 8 MB，原整园约 35 MB）；源模型查看、大屏与合作方控制台仍用整园。`?venueDetail=full` 可强制整园。
- 分身按需加载（每款约 0.65 MB，meshopt 压缩），自己的分身优先；在模型就绪前不放替身，名片可先打开。特写高清贴图只在框住某人时才下载。
- 本地无头 Chrome 实测（390×844，桌面 GPU）：手机首屏总传输约 17 MB，渲染约 190 万三角面、240 次绘制。这不是实体手机验收，正式活动前仍需目标机型实测。

## 8. 隐私与数据

- 进入只需一次明确动作（「进入」按钮上方写明同意范围）；不采集照片、声音、手机号、定位。
- 名片字段全部选填，保存前必须勾选同意。
- 联系方式三档可见范围；「相遇后可见」只在双方确认后，通过 `/api/me` 下发给对方，不进公共快照与大屏。
- 待确认的招呼只对双方可见；「先不了」不会通知发起方。
- 隐身后从公共世界、推荐、公共连线中移除；删除会清掉身份、会话、相遇和打卡记录。
- 内置 15 位人物与 7 条连线为虚构演示数据，不能替真人确认。
