# 碰一下：NFC / 支付宝触碰接入

这份文档定义相遇之庭这一侧已经实现的触碰协议，以及和支付宝「碰一下」或手环厂商联调时需要对齐的部分。**已实现**的是网页入口、标签解析、签名校验、防重放和对应动作；**未完成**的是支付宝正式接口、实体手环实机读写与身份核验（需要对方文档与沙箱）。

## 1. 一枚标签里写什么

NFC 芯片（或二维码）里只写一个 HTTPS 链接：

| 场景 | 链接 | 效果 |
| --- | --- | --- |
| 通用入口 | `https://<域名>/echo-campus/?entry=nfc` | 打开入场仪式，一键以分身进入 |
| 手环 | `…/?entry=nfc&tag=WB-investor-0042` | 同上，并识别为「投资人」类别（手环色），新来宾入场后自动带上 |
| 点位立牌 | `…/?tag=CP-future` | 已入场的来宾直接盖章、加分并打开护照；未入场的先入场再自动盖章 |
| 入口闸机 | `…/?entry=nfc&tag=GATE-south` | 仅记录为入口触碰 |

标签 ID 规则：`WB-<类别id>[-任意编号]`、`CP-<点位id>`、`GATE[-任意]`；也可以在活动配置 `tags` 里把厂商下发的任意 ID（如 `ALIPAY-BOOTH-01`）映射为手环/点位/入口。

## 2. 服务端接口

`POST /api/tap`，JSON：

```json
{ "tag": "CP-future", "ts": 1791000000, "nonce": "a8Fk2c91x0Lq", "sig": "<64 位十六进制>" }
```

- 已领取分身的设备带 `Authorization: Bearer <token>`；没有也可以调用（只返回标签含义）。
- 返回：`{ tag: {id, kind, category?, checkpoint?}, verified, attendee?, checkin? }`。
  - 手环：若来宾当前类别仍是默认「其他来宾」，改为手环类别（不会覆盖本人已选的类别）。
  - 点位：调用与网页按钮相同的打卡逻辑，同一来宾同一点位只计一次（`checkin.idempotent`）。
- 前端在页面加载后自动处理 URL 里的 `tag`（`AppUI.handleTap`），无需来宾操作。

## 3. 签名与防重放

设置 `ECHO_TAP_SECRET` 后，**每一次**触碰都必须带签名，否则拒绝：

```
sig = HMAC-SHA256(secret, `${tag}.${ts}.${nonce}`)，十六进制小写
ts    = Unix 秒，服务器时间 ±10 分钟内有效
nonce = 8–64 位 [A-Za-z0-9_-]，20 分钟内只能用一次
```

| 情况 | 结果 |
| --- | --- |
| 未配置密钥、`demoMode:true` | 接受未签名触碰，`verified:false`（仅演示） |
| 未配置密钥、`demoMode:false` | 403 `TAP_SIGNATURE_REQUIRED` |
| 签名错误 / 换了标签 | 401 `TAP_SIGNATURE_INVALID` |
| 超时 | 401 `TAP_EXPIRED` |
| nonce 重复 | 409 `TAP_REPLAYED` |
| 标签未登记 | 404 `TAG_NOT_FOUND` |

签名把 `tag` 绑进去，所以截获一次点位触碰无法改成别的点位，也无法重复使用。

## 4. 和支付宝「碰一下」对接的推荐路径

浏览器里永远不放支付宝密钥，也不把手环上的明文编号当成已认证身份。推荐让对方系统（支付宝小程序 / 活动后台）完成核验后，生成**带签名的跳转链接**：

```
来宾手机碰支付宝碰一下设备或活动手环
  → 支付宝侧识别（设备号 / 用户授权，按支付宝正式能力）
  → 合作方后端用共享密钥签名：tag + ts + nonce
  → 302 到 https://<域名>/echo-campus/?entry=nfc&tag=…&ts=…&nonce=…&sig=…
  → 相遇之庭页面 → POST /api/tap 校验 → 入场或盖章
```

页面会读取 URL 里的 `tag`、`ts`、`nonce`、`sig` 原样交给 `/api/tap` 校验，并立即从地址栏移除，刷新不会触发重放错误；未入场来宾先入场，再走常规打卡盖章，不会二次消费同一个 nonce。若对方的参数名不同，只需在 `AppUI` 构造函数里改映射。

联调前需要对方提供：

1. 碰一下打开的目标形态（H5 链接 / 小程序页面 / 是否必须在支付宝内）与未安装支付宝时的降级。
2. 能否在跳转前做服务端签名；签名算法、密钥交换与轮换方式。
3. 手环 UID / 卡号与活动身份的对应关系由谁维护；补发、挂失、换卡规则。
4. 点位是否每次触碰都回调；回调重试与幂等键。
5. 沙箱与生产域名、证书、回调白名单、技术联系人。

## 5. 现场降级

1. **首选**：碰一下 → 页面 → 入场 / 盖章。
2. **同页替代**：同一链接的二维码（大屏右下角、立牌背面）。
3. **网页按钮**：护照里的「演示盖章」仅在演示环境保留；正式活动可以按点位关闭。
4. **网络异常**：页面会提示活动连接不可用，场景仍可浏览；恢复后自动重连。离线补记目前未实现，需要活动方确定审批规则后再做。
