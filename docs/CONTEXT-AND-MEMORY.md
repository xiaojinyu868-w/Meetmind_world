# 上下文、记忆与 Package 架构

本文是 PRD.md 原则 P-1/P-3/P-4/P-7/P-8 的落地规范。核心命题：**上下文是这个产品唯一的资产，腐烂是唯一致命的失败方式。**

## 1. 上下文腐烂：定义与防线

**上下文腐烂** = 原始相遇信息在存储、摘要、转手、推断过程中逐步失真，最终系统里剩下的都是"模型觉得"，而不是"当时发生"。

防线（按执行顺序）：

1. **采集即冻结**：原始媒体（视频/音频/照片）落盘即只读，永远不被覆盖、裁剪、增强后替换。
2. **转写留存双份**：语音转写文本与原始音频并存；转写错误修正产生新版本，不改原始转写。
3. **推断永远可重算**：推断层任何条目都可被删除重算而不损失事实；反之绝不成立。
4. **摘要必须带指针**：任何摘要/标签必须能指回事实层的原始片段（文件 + 时间区间）。指不回去的推断不允许入库。
5. **定期对账**（MVP2 起）：抽样检查推断层条目，验证其事实指针有效、置信度标注完整。

## 2. 事实层 vs 推断层（P-3）

| | 事实层 Facts | 推断层 Inferences |
|---|---|---|
| 内容 | 照片、音频、视频、转写原文、时间地点、用户手动确认的身份 | 兴趣标签、需求判断、关系强度、匹配建议、摘要 |
| 写入者 | 采集管线 + **用户显式确认** | 模型/规则，自动写入 |
| 可变性 | 只增不改（append-only，编辑 = 新版本） | 可随时重算、覆盖、删除 |
| 必备元数据 | 采集时间、采集设备、来源事件 ID | 来源事实指针、模型版本、置信度、生成时间 |
| 谁能读 | 按权限圈层（见 §5） | 同左，但可单独降级（如只共享推断不共享原始照片） |

**实现约定**：物理上分开存储 —— `facts/` 与 `inferences/` 两个命名空间；代码上两个写入路径，推断层写入函数没有事实层的写权限（对应 ARCHITECTURE.md §5 权限矩阵）。

**视觉化生成物的归属（2026-08-03 补充）**：AI 生成的视觉产物——个人场域（FR-2.11）、人物图片贴图（P-6）、场景复刻图——同样是**推断层的视觉化产物**，不是事实。它们必须：标注为生成物、携带来源素材指针、可随素材更新重算、可删除而不损失任何事实。事实层的"相遇第一现场"（原始照片/视频）永远独立保留，生成物不得替换或覆盖它。

## 3. 核心对象：人物 × 事件（P-4）

产品底层**不是**"一个人一条档案"，而是两层对象：

```
Person（人：稳定身份，人脸/声纹/用户确认的身份）
  └── Encounter × N（每次相遇：一个事件，一份上下文）
        └── 指向该次相遇产生的事实与推断
```

- 同一个人在不同黑客松相遇两次 = 1 个 Person + 2 个 Encounter，各自的现场、谈话、照片独立保存。
- Person 级别的"综合印象"是推断层视图，由 Encounter 聚合而来，**可重算**。

## 5. 权限圈层（P-8，产品机制而非补丁）

每条数据（事实或推断）带一个 `privacy` 字段，四级：

| 级别 | 值 | 含义 |
|---|---|---|
| L1 | `self-only` | 仅记录者自己可见（**默认值**） |
| L2 | `agent-usable` | 自己的 Agent 可用于互动与匹配，但不展示给其他用户 |
| L3 | `org-shared` | 组织空间内可见（MVP3） |
| L4 | `public-approved` | 经本人同意后公开 |

规则：

- 默认 L1；升级必须显式操作，降级随时允许且立即生效。
- Agent 互动时只能携带 ≥ L2 的信息；Agent 输出的对话记录继承其输入中**最严格**的级别。
- 被记录者注册后可查看并主张自己 Package 的级别（FR-3.1）。
- 人脸照片、声纹永不允许 L4，除非本人显式签署授权（MVP3 才实现该流程，MVP1/2 直接禁止）。

## 6. 记忆分层（Agent Runtime 侧）

对应 ARCHITECTURE.md `backend/agents/memory/`：

| 层 | 内容 | 生命周期 | 自进化可写？ |
|---|---|---|---|
| 场景记忆 | 某次相遇/某次会议的完整上下文 | 长期，但事实部分只读 | 只能新增 |
| 短期工作记忆 | 当前任务、当前对话的临时状态 | 会话级，可丢弃 | 可以 |
| 长期记忆（人物事实） | PersonPackage 事实层 | 永久，append-only | **禁止**（只能用户确认流程写入） |
| 推断记忆 | memory.md / relations.md（关键词索引） | 可重算 | 可以（受限：必须带事实指针） |

人物目录约定（`backend/people/<person_id>/`）：

- `profile.json` —— 事实 + 权限（本文件即 Package 存储形态）
- `memory.md` —— 推断层记忆，供 Agent 快速读取；每条目附 `(source: facts/..., conf: 0.7)`
- `relations.md` —— 关系网络，纯关键词匹配格式：`人名 | 关系 | 关键词1, 关键词2 | 来源事件`

## 7. 增量上下文主动捕获（P-7）

系统主动索取增量信息的标准路径：

1. Agent 互动或用户浏览时，发现上下文缺口（如"A 的需求明确，但不知道预算范围"）。
2. 生成**具体可执行的微信操作建议**：不是"去问问"，而是给出可直接发送的话术草稿 + 要确认的 1-2 个点。
3. 用户在微信真实执行（系统不接管微信，只给建议）。
4. 用户回填结果（一键粘贴/语音/确认选项）→ 进入该 Encounter 或新建 Encounter → 事实层新增，推断层重算。

**边界**：建议必须基于已授权上下文生成；不得诱导用户去套取对方未授权的信息。

## 8. 上下文量能与交互场景对照（P-1 的执行表）

| 累计上下文量 | 解锁的交互场景 | 未解锁（禁止提前做） |
|---|---|---|
| 1-5 个 Package | 世界浏览、资料包查看、场景语言点位交互、人脸/姓名检索 | 任何 Agent 间互动 |
| ≥10 个 Package | 圆桌会议、Agent 互相访问、市集场景、个人场域生成 | 价值推送（样本不足，噪声大） |
| 现场群体模式（合照 ≥5 人，FR-2.12） | 批量建档、第一印象互写、破冰互动、大屏演示（2.H） | 实时联机（远期，FR-3.6） |
| ≥10 个 Package + 推断层覆盖率高 | 价值匹配推送、微信行动建议（2026-08-03 暂缓，待 MVP2 后重议） | 跨用户网络 |
| 多用户 + 本人确认流程上线 | 网络互联、组织空间 | — |

此表是产品功能开关的依据，编码为 feature flag 配置（ROADMAP X.6），而非口头约定。
