# Agent 交互逻辑优化 · 策划草案（待评审）

> 背景：集市"有目的的串门"已上线（配对闸 + 授权对话），咖啡厅仍是"每 tick 随机/LLM 决策"的时间驱动。用户反馈：乱走无意义 → 事件驱动为主、稀疏心跳；玩家应能下场交谈。本文是下一轮集中优化的方案草案，**评审通过后才动实现**。对应 ROADMAP：M1.1 / M1.3 / 2.A.1a / 2.A.3。

## 1. 调度架构：从时间驱动到事件驱动（M1.1）

### 现状问题
- 咖啡厅：每 tick 都要"演"，无增量信息时产生随机漫步——伪活跃，损害体验。
- 大厅：串门已有配对闸，但触发仍靠概率，不是真正的事件。

### 目标架构：事件队列 + 稀疏心跳

```
触发器（事件源）                    调度器                        世界
─────────────────────────────────────────────────────────────
Package 入库（confirm）      ┐
推断层更新（pipeline 重算）  │   优先级队列（高→低）：
用户关注（走近/点开/停留）   │   1. 玩家在场交互（打断一切）
匹配被发现（≥阈值）          ├── 2. 系统事件（新人/匹配/会议）
约定会议到点                │   3. 关系活动（串门/叙旧）
（MVP2）推送被反馈有用       │   4. 心跳（无可说内容=安静）
─────────────────────────────┘
        ↓ 无事件时：世界保持安静（守摊/入座/阅读状）
```

- **心跳稀疏化**：cafe 2s tick 不变（渲染需要），但行为决策只在"有事"时发生；心跳每 N=30 tick（≈1 分钟）检查一次"有没有值得做的"，没有就继续安静。
- **玩家在场是第一优先级**：玩家走近某人 ≤2.5m，对方停下手头事转身面向玩家（已实现的雏形），玩家离开时 3s 后恢复原活动。
- 咖啡厅的圆桌会议从"每 20 tick 自动"改为"约定触发"（用户发起 / 匹配事件触发的议题会议）。

## 2. 玩家与 Agent 单聊（M1.3）

- **入口**：走近 + 点击人物 → 资料包面板底部/世界内气泡发起「和 TA 聊聊」（二选一，评审定：面板内对话框 vs 世界内气泡流）。
- **内容边界（P-8）**：对方只基于其 package 中 ≥L2 授权内容应答（deepseek），system prompt 注入 `authorized_agent_view`；界面常驻标注「基于 TA 授权信息的模拟，非真人」。
- **结构化开场（不是空白输入框）**：系统根据双方上下文给出 2-3 个开场建议（"问 TA 海边摄影展的后续"、"聊聊上次的河堤"），降低冷启动；也允许自由输入。
- **接口**：`POST /api/v0/agents/{id}/chat`（IF-6 提前项）：`{message} → {reply, cited_facts[]}`；`cited_facts` 让回答可溯源（P-3 精神：模型的话要指得回事实）。
- **沉淀**：玩家与 Agent 的对话**不自动入库**；用户可选择"把这条记进 TA 的资料包"（手动 → 推断层，带"来自玩家转述"标注）。

## 3. 对话质量：从打招呼到有内容

现状：串门对话是"好久不见/最近怎么样"级。优化方向：

1. **共同上下文驱动**：对话 prompt 注入双方交集（共同 tags、relations.md 的关系备注、最近事件）——"你上次说的海边摄影展，后来办了吗？"而不是寒暄模板。
2. **信息量闸门**：每场对话生成后，由 deepseek 自评"这段对话是否产生了新信息（0/1）"；无信息量的对话不入事件缓冲（不打扰用户），有信息量的才可能成为"匹配候选"。这是 M1.1 事件驱动中"推断层更新"触发器的来源。
3. **对话即推断**：有价值对话的结论（如"两人都需要教育渠道"）写入推断层（带双方事实指针 + 置信度），为 2.B 价值匹配积累素材——串门不只是表演，是数据生产。

## 4. 串门的后续沉淀

- 关系强度：relations.md 增加 `last_interaction_at` 与 `interaction_count`（串门/会议/单聊累计），影响后续配对优先级（熟人更可能深聊，陌生人更可能破冰）。
- 世界可读性：资料包面板"系统认知"区可展示"TA 最近和谁聊过"（≥L2 事件），让用户感知世界在演化。

## 5. 评审要拍板的问题

1. 单聊入口形态：面板内对话框（实现轻）还是世界内气泡流（沉浸但成本高）？
2. 心跳频率：1 分钟级合适吗？是否需要"世界安静时灯暗一点"的氛围反馈？
3. 对话信息量闸门：先简单自评 0/1，还是直接上"匹配候选"打分（复杂但一步到位）？
4. 玩家对话是否允许影响推断层（当前方案：仅手动沉淀，防污染）？
5. 实施顺序建议：先做 2（单聊，用户感知最强）→ 1（调度重构）→ 3/4（质量与沉淀）。是否同意？
