# 活动模式（Event Mode）策划与计划 —— MeetMind × 阿里巴巴联合活动

状态：v0.2（2026-09-15 决策后进入排期）。对应 ROADMAP 3.C.2「活动模式：黑客松/展会批量入场」。
这是一份"要做什么、做到什么程度"的文件，不是 PRD；决策记录与任务分解见第 10、11 节。

## 0. 已定决策（2026-09-15）

- **目标档次：直接按 L2 活动可用版排期，L1 演示原型是第一个里程碑**（本周内上线可演示）。
- **规模：尚未确定，按 300 人规划**（容量、压测、手环数量按 300 准备，架构留到 500）。
- **身份：手环即身份、免登录**；微信绑定放到活动后的个人卡片。
- **阿里角色：尚未谈到，先按联合主办准备**（效果与品牌优先）；百炼/阿里云的技术合作叙事作为备选材料准备。
- **分身路线：端侧秒级像素分身 + 云端 AI 精修**；精修在 L2 做，端侧版是永远可用的兜底。
- **已完成的后端签到事件流保留，作为 L1 地基提交。**

## 1. 一句话定位

**碰一下，你就在地图上了。** 把一场线下活动的人流，实时变成一张会生长的线上 3D 地图：
每个参会者碰一下 NFC 手环，30 秒内拥有自己的像素分身，出现在大屏地图的兴趣分区里；
活动中分身替你留下足迹和相遇；活动结束，每个人带走一张属于自己的"活动地图"。

它延续 MeetMind 的主张——"让相遇有地方可以回来"——但把入口从"一张合照"换成"一次碰卡"，
把场景从"小镇"换成"这场活动的场地"。

## 2. 三个视角，各自要得到什么

| 视角 | 触发时刻 | 他得到什么 | 我们要证明什么 |
| --- | --- | --- | --- |
| 参会者（手机） | 领到手环、碰一下 | 30 秒有分身；看见自己在地图上；活动后一张可分享的卡片 | 低门槛、有惊喜、愿意分享 |
| 现场大屏 | 全程 | 活动氛围：地图在生长、有人刚入场、分区在变热、结尾全员合照 | 3D 世界是活动内容本身，不是装饰 |
| 主办方 / 阿里 | 活动前后 | 品牌化的活动空间；签到/热区/相遇数据；可复用的活动模板 | 我们能把"人流"变成"资产"，且可交付 |

## 3. 参会者旅程（活动可用版）

```text
活动前   领手环（NTAG 标签写入 URL：…/event.html?event=<活动>&tag=<手环UID>）
入场     手机碰手环 → 系统弹出链接 → H5 落地页（无需下载/登录，手环即身份）
         → 自拍一张（照片不出手机，端侧 1 秒生成像素分身；可微调发型/眼镜/穿搭色）
         → 写一句"我是谁 / 想聊什么"，选一个兴趣分区
         → 提交：大屏上分身从入口走进分区；手机上看到"你在地图上的位置"
活动中   展位设 NFC 点位：碰一下 = 分身走到该展位，留下足迹
         两个人互相扫对方手机上的二维码（安卓可直接碰手环）= 记录一次"相遇"，大屏亮起一条连线
         分身在分区里替你"社交"：相邻分身互相展示一句话介绍（不调模型、零成本）
         可选：云端 AI 精修分身（10–30 秒），完成时大屏上分身"换装"闪一下
结尾     主持人触发"合照时刻"：全员分身聚到舞台前，大屏定格出图
活动后   每人收到 H5 卡片：分身、入场时间、足迹、遇到的人、全员合照；分享到微信
         打开卡片时可绑定微信 → 分身进入 EchoWorld 常驻世界（后续产品衔接）
```

## 4. 要展示的六项能力（对阿里的叙事）

1. **现场入口**：NFC / 二维码 / 微信三种入口共用一条链路；群体冷启动最低门槛（已有二维码与微信登录）。
2. **数字人分身**：两级生成——端侧秒级像素分身（隐私友好，原图不上传）+ 云端 AI 精修
   （复用现有 qwen-vl / gpt-image 像素重绘管线的思路，用当前一代模型重做）。
3. **线上地图**：程序化生成的 3D 活动场地，分区/容量/主题可配置，是"活动模板"而不是一次性场景。
4. **实时大屏**：多设备事件 → 有序事件流 → 大屏世界直播；断线重放、幂等，不会重复出人。
5. **相遇与足迹数据**：谁来了、去了哪、遇见谁——沉淀为个人卡片与主办方报告；事件流可审计、可回放。
6. **AI 与模型合作点**：分身、场地贴图、破冰推荐都走阿里云百炼（qwen 系列）——对阿里是"用他们的模型把线下人流变成线上世界"。

## 5. 做到什么程度：三档

### L1 演示原型（给阿里看，1 周内可交付）

目标：一台电脑 + 几部手机，10 分钟讲完整个故事，视觉上"值得合作"。

- 大屏页：3D 夜景活动场地（入口 NFC 光环、中央舞台屏、6 个兴趣分区、灯串/树/水面、Bloom 后处理）；
  分身从入口走进分区，姓名牌、气泡介绍；HUD：在场人数、分区热度、最新入场、入场二维码。
- 手机页：模拟/真实碰卡（URL 参数或安卓 Web NFC）→ 自拍 → 端侧像素分身 3D 预览与微调 → 选分区 → 提交 → 看到自己在地图上。
- 演示模式：机器人分身按节奏入场，无人也能演示；真实手机与机器人可同屏。
- 后端：活动签到事件流（幂等、分区槽位、皮肤 PNG、二维码）。**已完成并通过 7 项测试，未提交。**
- 不做：微信登录、多点位足迹、相遇、AI 精修、活动后卡片、大规模容量。

验收：手机 30 秒内完成入场；大屏 100 个分身 60fps；三种设备（iPhone Safari / 安卓 Chrome / 微信内）都能走通落地页。

### L2 活动可用版（活动当天真跑，3–4 周）

在 L1 上增加：

- 真实 NFC 手环（NTAG213，写 URL 记录）；展位点位标签；相遇（扫码互认，安卓可碰手环）。
- 云端 AI 精修分身（异步任务队列、失败回退端侧版、原图生成后即删）。
- 合照时刻、活动后个人卡片 H5（可分享）、主办方后台（人数/热区/相遇图/导出）。
- 容量 300–500：分身合并网格 + 皮肤图集 + 动画降级；大屏独显机器；后端加房间 token、限流、独立部署或扩容。
- 品牌：活动名、阿里视觉规范进入舞台屏与分区标识。

验收：碰卡成功率 ≥95%；≥70% 参会者入场；人均 ≥2 次互动（足迹/相遇）；卡片打开率 ≥50%；全程无重复分身、无丢事件。

### L3 产品化（活动后）

分身进入 EchoWorld 常驻世界与「每人一岛」；Agent 化分身（一句话人设 + 记忆）与破冰推荐；活动模板化可售卖（主题/分区/品牌一键配置）；多活动跨场复用身份。本次不承诺。

## 6. 现在这个时代怎么做（与旧版的差别）

| 旧做法（2026-08） | 这次 |
| --- | --- |
| Blender 手搓固定场景，12 个摊位硬上限 | 程序化场地 + 参数化模板（分区数/容量/主题色/品牌位），AI 生成贴图与道具作为可选层 |
| 合照离线批处理生成分身，分钟级 | 端侧 1 秒出像素分身先上地图，云端 AI 精修异步"换装"，两级体验 |
| 房间最多 7 人、大厅 12 人 | 事件流驱动的活动世界，L1 百人、L2 五百人 |
| 世界是产品本身，观众是使用者 | 大屏是"世界的直播"，观众先看见再参与，参与后带走 |
| 模型贯穿一切 | 模型只在明确的增值点介入（精修、推荐、贴图），核心链路不依赖模型、零额度也能跑 |

## 7. 技术方案

### 复用

微信登录与二维码（`wechat_auth.py` / `mobile.py`）、像素角色资产契约（128×128 atlas、7 骨 GLB、8 个 Action）、
房间 WS 与大屏只读视角的经验（`RoomClient`）、部署管线（CI + cron 部署）、事件流理念（`world-events.v1.jsonl`）。

### 新建

```text
手机碰卡页 event.html?mode=tap      大屏页 event.html?mode=screen        主办方后台（L2）
        │  POST /api/v0/events/{id}/checkins        │ GET …/checkins?since=seq（2s 轮询，L2 升 WS）
        ▼                                            ▼
  活动签到事件流  <data>/events/<id>/checkins.v1.jsonl（追加、seq 递增、幂等）
  皮肤 PNG        <data>/events/<id>/atlas/<checkin>.png（端侧生成，非照片）
  L2：footprints.v1（点位足迹）、encounters.v1（相遇）、精修任务队列、卡片渲染
```

- 前端：Vite 多页入口 `event.html`（与主站同仓同部署，线上即 `/echoworld/event.html`）；
  `src/event/` 下：像素皮肤生成器（纯函数，可单测）、场地布局（纯函数）、Three.js 场地与分身系统、两个页面壳。
- 分身：复用 `host.glb` 作为身体模板，克隆后只换 atlas 贴图；L2 合并网格与皮肤图集。
- 大屏：EffectComposer + UnrealBloom，暖色夜景；相机在环绕与"跟拍新入场者"之间切换；相邻分身气泡。
- NFC 事实：iPhone 后台读取 NDEF URL 直接弹链接（Safari 打开），安卓系统浏览器打开；**微信内没有 Web NFC**。
  因此正式路线是"标签写 URL"，Web NFC 只作安卓增强；"手环即身份、免登录"是活动当天最稳的方案，微信绑定放到活动后卡片。

### 视觉方向

延续项目调色：森林绿 / 珊瑚红 / 暖金的夜景，灯串与篝火，像素分身；不用科技蓝紫渐变。
活动场地 = 一座夜色中的浮空广场：南侧 NFC 光环入口，中央舞台与 LED 屏，六个分区环绕，外围水面与树。
阿里品牌元素只出现在舞台屏、分区旗与入场卡片上，需要对方提供规范。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 现场网络差、手机弱网 | 落地页极轻（<1MB 首屏）；端侧生成不依赖网络；提交失败本地重试；大屏轮询容忍断线重放 |
| iPhone 微信内无法读 NFC | 标签写 URL 走系统浏览器；微信内提供扫码入口；手环即身份不依赖微信登录 |
| 大屏性能（几百分身） | L1 克隆上限 120；L2 合并网格 + 皮肤图集 + 远处降级为静态；独显机器 |
| 模型额度 / 欠费（9/12 出现过） | 核心链路零模型依赖；精修异步且可回退；活动前充值并设额度告警 |
| 隐私与授权 | 原图不上传（端侧）或生成后即删（精修）；像素重绘不复刻人脸；入场页明示授权 |
| 服务器"可信单机" | 活动版加房间 token 与限流；活动期间独立进程/机器，不与 EchoWorld 主世界共享状态 |
| 需求膨胀 | 严格按 L1→L2 分档；L3 项一律记入 ROADMAP 不进本次范围 |

4. 预算：手环（NTAG213 约 ¥2–6/个，300 人约 ¥1000–2000）、精修模型调用（约 ¥0.1–0.5/人）、服务器扩容。
5. 授权文案：拍照/像素重绘/数据用途的现场提示与法务口径。
