# 共同空间实验：两个人，把一个现实决定做出来

状态：建议的框架技术样例，2026-09-12。未获用户确认商业转向；不改现有线上咖啡厅/场景组资源。
依据：[付费任务研究](MOTIVATION-EVIDENCE-2026-09-12.md)。

## 可体验任务

“我们准备搬进同一个小房间。一个人白天要在家工作，另一个人希望留下运动空间；还想保留一件有共同来历的物品。我们需要在买家具前决定怎么放。”

进入时展示一个有实际尺寸的合成房间与少量候选家具，而非空世界。两人分别选择自己想保留的用途与物品，查看两个方案，移动物件或提出修改，可以结束于双方接受同一版本，也可以是“没有共同方案”“需要补充测量”或“暂不决定”。每种终态均可导出方案摘要、分歧、待测量项和本人选择的下一步行动；不要求为完成实验而接受。

为了检验原方向，首次样例必须包含两条有来源、可纠正的共同经历，例如：
一方说“上次我们在客厅开视频会议，另一方被打扰”，另一方可确认、补充或否认；
两人一起做过一件物品，明确决定保留它还是只保存照片。只有本人确认的用途/要求进入约束，
不能把单方陈述自动当成共同事实。后来补充“今后每周只有一天在家办公”时，应能追溯调整相关偏好，
保留其他约定，并解释哪些建议来自旧上下文。原经历撤回后，只撤掉该依据，不自动替本人撤销已经独立确认的要求。

这些经历在字段层面可选以便框架复用，但本验收样例必须存在。若移除共同历史后体验完全相同，
该样例只能证明空间编辑能力，不能证明真实经历进入持续世界的价值。

首次演示全用合成尺寸、人物、预算与经历，明显标注。照片转精确测量不属于已完成能力；真实尺寸由参与者确认。能移动家具也不代表满足建筑、消防、无障碍或装修规范。

## 3D 必须做的工作

- 同一 ID 对应家具的用途、尺寸、位置、来源和选择状态，2D 平面与3D一致。
- 单位米；边界、门口预留区、不可重叠区及需要保留的活动区可见。
- 默认规则只证明简单俯视几何约束；结果显示具体冲突对象与原因，不能叫“专业合规验收”。
- 修改方案只影响指定对象。约束改变后重算受影响项；未改对象的 ID、来源与用户决策保留。
- 人物表达本人的要求，系统可提出折中；模型不能替另一位参与者接受。
- 共同接受绑定完整决策快照的版本，覆盖布局、尺寸、测量依据、用途、预算、约束和妥协条款。
  任一影响决策的内容改变都产生新版，旧接受保留为历史，不能继续显示为当前双方同意；
  一方不能替另一方放宽其要求。纯渲染细节变更须明确区分，不能夹带改变尺寸或用途。
- 现实行动仍由本人确认，例如测量门宽、确认家具尺寸、决定购买。模拟中通过不等于现实安装成功。

## 两个问题要用不同对照回答

已有 Planner 5D 等产品可共同设计房间。本实验不以“能摆家具”作为创新结论，分开验证两项假设：

1. **3D展示是否有帮助：**同样的上下文、协商、约束、历史和操作，只改变可操作2D平面/3D呈现。
   任务信息等价、顺序交替。这个对照最多支持呈现方式的结论，不能证明持续记忆或AI协商有用。
2. **上下文与持续协商是否有帮助：**固定同一呈现，比较A“参与者手工写要求、共享编辑、普通版本历史”
   与B“根据已确认经历给出可追溯建议，经历纠正后提示受影响的要求，仍由本人决定”。两组都能查看相同原始材料，
   不把记忆故意藏在对照组之外。比较遗漏/误推需求、人工重复说明、返工及双方是否清楚同意内容。
   只有B才会出现的自动化建议必须记录错推与纠正成本。若优势只是预填表单，不能归功于整个持续世界。

首批4–6对只做形成性观察，可分配等难度任务与交替顺序，不能同时估计这两个因素的因果效果；
若要定量结论，应据初步变异和目标效应另设计样本量与实验。也不能在同一小样本上试许多指标后只报告获胜项。
当前抽象对象列表的2D基线不够公平，需要可操作平面布局。美术质量会影响判断，不能以粗糙实现证明3D无用。

## 最小领域数据

World -> SpaceSpec -> ObjectInstance -> Constraint -> LayoutRevision -> ParticipantDecision -> Action。

- SpaceSpec：单位、边界、门口预留区、用户确认的测量来源。
- ObjectInstance：稳定 ID、模板/资产引用、用途、尺寸、变换、来源经历 ID（可选）、是否锁定。
- Constraint：提出者、适用对象、规则及阈值；区分不可违反与偏好，记录明确接受的妥协。
- LayoutRevision：基于哪个版本、增量操作、冲突报告、提出者及原因。
- ParticipantDecision：本人、版本、接受/拒绝/待修改；不能对“当前”这种易变化指针作永久同意。
- Action：具体待办、责任人、时间、完成标准和结果来源，复用既有独立行动能力。

模型适配器输出受限结构/补丁；离线演示由明确标注的人工样例驱动。付费账户恢复后再测真实生成，不冒充实时 AI，不重试已确认欠费的账户。

## 技术复验与真人验证分开

**技术证据：**在至少两个浏览器完成真实独立选择、空间冲突可见、局部修改保留对象、并发修改有可解释冲突、旧版接受不冒充新版接受、刷新恢复并导出同一版本。合成用例应包含一次无法满足全部要求的情况，系统不能编造可行解。

**探索性真人任务：**首批建议 4–6 对近期确有搬家/布置需求的成年人，每对约30分钟；这是寻找严重问题的小样本，不估计市场或统计显著性。招募需实际渠道，当前尚未开展。
记录原来怎么决定、最近一次争执/返工与费用、任务能否完成、主持人干预、误解、耗时、各自是否接受、是否真的采取下一步。允许不想共同讨论或中途退出，不能把拒绝算成“关系失败”。

**产品证据：**之后需清楚交付范围的真实购买选择或付费订单及成本核算；本轮没有报价、收款或承诺交付。

## 放弃或调整条件

- 现实任务用平面图/现有协作工具更容易完成：保留领域框架，降低3D在该场景的优先级。
- 用户不愿提供尺寸/约束，启动成本超过收益：换触发场景或输入方式，不能改成催用户打卡。
- 两人都喜欢视觉但没有形成更清楚的决定，也不愿现实使用：不以停留时间或截图代替价值。
- 通用模型加普通编辑器已足够，框架没有降低开发成本：收紧研究差异，停止堆完整设计软件。
- 技术卡在模型可用性：继续可解释的人工样例及编辑交互，模型效果单独保持未验证。
