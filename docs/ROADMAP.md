### 1.D 检索与恢复

> **路线修正（2026-08-03，产品调性决策）**：检索是底层能力，不是用户场景——没有用户会拿着新人的照片来"查库"。本产品不是通讯录/数据库工具，"恢复上下文"的主路径是：**世界即入口**（在世界中遇到 TA、点开即得）与**系统主动浮现**（再次相见时系统认出并提示，而非用户主动搜）。1.D 各项据此降级为能力储备，不作为产品入口打磨。
- [x] 1.D.1 姓名/关键词检索人物（能力保留在 API 层，不作为主交互入口）
- [ ] 1.D.2 人脸识别提示（重构）：从"用户拍照去检索"改为"系统认出并主动提示'这是你在 X 认识的 TA'"——眼镜/摄像头场景的系统主动行为；接口保留，产品形态待 MVP1.5 策划
- [ ] 1.D.3 事实层完整性自检：重开页面后资料包与原记录逐字节一致（NFR-1.1 验收）

## MVP 1.5 · 空间化与体验修正（2026-08-03 产品决策）

> 来源：用户实测反馈后的路线对齐——世界不应该是"人乱走的客厅"，检索不应该是入口；下一步把"个人 package 的前端呈现"空间化。

### M1.A 驱动与交互

- [ ] M1.1 事件驱动调度改造（即 2.A.1a，优先级提前）：世界默认安静；事件队列触发（入库/推断更新/用户关注/匹配发现/约定会议）+ 稀疏心跳；规则访问带目的性。**实施前需先完成调度策划评审**
- [~] M1.2 "人+场景"空间模式（主线）：**展位大厅阶段已完成**（2026-08-03：大厅 Expo Hall 为默认一级世界，每 Package 一个展位[名牌/人像/相框/AI 标签]，人静立展位不走动，点击开资料包，咖啡厅保留为活动世界，`?world=hall|cafe` 切换）；"家"阶段（进入 TA 的空间、相遇纪念物陈列）后续做
- [ ] M1.3 玩家与 Agent 单聊：走近/点击发起对话，对方基于 ≥L2 授权内容应答（deepseek），界面标注"基于 TA 授权信息的模拟"；接口 `POST /api/v0/agents/{id}/chat` 登记入 API.md（IF-6 提前项）

### M1.B 美术对齐

- [ ] M1.4 图片风格统一：portraits 与现场照占位图按 storybook 风格重渲染（用仓库内队友 Blender 脚本）；真实物理输入打通后由 pipeline 按同一规范生成替换

> 前置：MVP1 验收通过 且 人均 Package ≥ 10（P-1 上下文量闸门）。
> 完成功能开关见 CONTEXT-AND-MEMORY.md §8。

### 2.A Agent Runtime

- [~] 2.A.1 规则调度器：每日走动、访问 N 个 Agent、定期圆桌（参数可配）（skill + LLM 决策 + 规则兜底已落地并产对话/会议，参数化与完整规则待 MVP2）
- [ ] 2.A.1a 调度优化（产品决策 2026-08-03）：**从时间驱动改为事件驱动为主 + 稀疏心跳**。世界默认安静（无增量信息不演化）；活动由事件队列触发：新 Package 入库 / 推断层更新 / 用户关注或走近 / 匹配被发现 / 约定会议；心跳稀疏（分钟级）且无内容时保持安静。规则同步增加目的性（访问由推断层匹配驱动，非随机）

- [ ] 2.A.3 Agent 交互协议：结构化信息交换 schema（我是谁/我有什么/我需要什么/授权范围）（FR-2.3）
