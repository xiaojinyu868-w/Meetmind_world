# EchoWorld 美术协作提示词（画面/风格负责人专用）

> 用法：本文件整体转发给负责画面风格的协作者（人或 AI 均可）。自包含，无需其他上下文。
> 工程侧联系人见文末"接口边界"。本文件版本：art-brief.v4（2026-08-03，依据 P-6/ADR-6 重写）

---

你负责一个 3D 智能体社交产品 **EchoWorld** 的全部视觉资产与美术风格。产品是"把现实中的相遇变成生活在 3D 世界里的智能体"：用户在自己的关系集市（一条 low-poly 露天街道）里走动，每个认识的人有一个摊位，点开能看到真实资料包；市集街上有一间咖啡厅小屋用于熟人交流。当前为 MVP 阶段。

**画风已定稿（2026-08-03，P-6/ADR-6）：低多边形场景 + MC 体素人物 + AI 生成图片贴图。** 不做写实、不做二次元。具体基调：

- **场景低多边形**：哑光材质（roughness ≥ 0.7），微缩模型（diorama）感，暖色柔光 + 长软阴影——参考已交付的集市街道（`public/models/echo_world_market_street.glb`：石板路/红白条纹篷/彩旗/路灯/树木）。
- **人物 MC 体素（voxel）**：固定体素身体 + **AI 根据真实照片生成的图片贴图**（头部五面 + 身体 atlas），目标是"看一眼能认出是谁"。参考已交付的 `public/models/characters/photo-derived/voxel/*.glb` 与 `public/textures/characters/voxel/*_atlas.png`。
- 设计心理目标：每个新人物 = 集市里多一个属于你的摊位，"街道逐渐热闹"是产品的核心视觉体验。

## 一、你要交付的 4 类资产

### 1. 人物模型与贴图管线（最高优先级，P-6 的落地）

正式方向：**每个真实的人 = 一个体素 GLB + 一套 AI 生成贴图**。

```
真人照片（一张或多张）
  → AI 生成图片贴图：头部五面（正/左/右/后/顶）+ 身体 atlas（服装/配色）
  → 体素 GLB 组装（固定体素身体模板 + 动态贴图槽位）
  → 登记入资产白名单 → 部署
```

你（美术）的职责：

- **制定贴图风格规范**：贴图生成 prompt 模板（像素密度/色块大小/风格词/配色提取规则）、体素分辨率规格（头/身/四肢的体素格数）、atlas 布局约定——管线产物必须像你的风格；
- **交付基准人物**：2-3 个手工精修的体素人物 + 对应贴图，作为管线质量锚点；
- **体素身体模板**：男女/高矮 2-3 个体型变体（固定模板，管线按人只换贴图）。

硬性技术契约（管线产物与手工模型都必须满足）：

- 格式：GLB，单个无骨骼刚性模型（**不需要骨骼、不需要动画**，移动/入座由程序做刚体变换）。
- 规格：身高 **1.65 米**（程序按米制摆放）；原点在**脚底中心**；面朝 **+Z 方向**；根节点命名 `ROOT_Character`（白名单条目有 `root_node` 字段，按条目读取）。
- **贴图槽位是硬接口**：头部五面（front/left/right/back/top）与身体 atlas 使用**独立命名材质/UV 槽**（槽位命名与已交付 voxel 人物一致，见 `blender/build_photo_character_modes.py`）；贴图替换走 `NearestFilter`（像素感，禁线性模糊）。
- 面数预算：单个人物 ≤ 3k 三角面；贴图 atlas ≤ 512×512；文件 ≤ 2MB。

### 2. 场景模型

- 集市街道的迭代（更长可扩展的街）+ **新场景模块**：摊位变体、小屋门面（咖啡厅已在）、后续应用入口（电影院等，占位即可）。
- 格式：GLB，米制，原点在场景中心地面，面朝 +Z；材质哑光。
- 面数预算：整条街 ≤ 150k 三角面；单个模块 ≤ 15k。
- **碰撞壳**：场景内需要阻挡的物体（摊位/灯杆/树木/建筑）放置 `COLLIDER_*` 空物体（自定义属性带半径或盒尺寸），构建脚本导出到 manifest——程序按 manifest 生成碰撞（不再硬编码）。
- 程序用 2D 圆形/盒阻挡做碰撞，不需要精确碰撞网格。

### 3. 人物头像（资料包面板用）

- 正方形 PNG，≥ 1024×1024，统一渲染规范：由该人的体素模型渲染（固定机位正面胸像、柔和顶光、暖色纯色/微渐变背景），保证头像与世界里的小人是同一个人。参考已交付的 `public/portraits/`（`blender/render_portraits_storybook.py` 管线，可复用改体素版）。

### 4. 视觉风格基调（style tile）

- 一页风格定义：主色板（含 hex）、辅色、哑光质感、灯光氛围（暖色夕阳/室内暖光）、字体建议。工程侧翻译成 CSS 变量和 Three.js 灯光参数，你只出定义，不写代码。

## 二、硬性技术约定（违反即无法入库）

1. 一律 GLB（二进制 glTF），PBR 材质；不交付 .blend/.fbx/.obj 作为最终产物（源文件自行保留）。
2. 米制单位；Y 轴向上；面朝 +Z。
3. 文件命名：全小写蛇形，带语义和日期，如 `echo_world_market_stall_20260810.glb`。
4. 每次交付附一行 JSON 资产条目（工程侧录入白名单）：

```json
{
  "asset_id": "character.person-xxx.voxel.v1",
  "kind": "character",
  "url": "models/characters/photo-derived/voxel/person_xx.glb",
  "version": 1,
  "root_node": "ROOT_Character"
}
```

5. **只增不改**：已入库的资产不改文件内容，迭代 = 新文件 + `version` +1 + 新 asset_id（v2）。旧版本可能正在被线上使用。

## 三、验收清单（交付前自查）

- [ ] GLB 在 https://gltf-viewer.donmccurdy.com/ 打开正常，比例、朝向正确
- [ ] 人物贴图槽位齐全（头五面 + 身体 atlas），NearestFilter 下像素感正确
- [ ] 场景含 `COLLIDER_*` 空物体且 manifest 导出碰撞列表
- [ ] 文件大小：人物 ≤ 2MB，场景 ≤ 10MB（web 加载预算）
- [ ] 头像 PNG 正方形、风格统一、与体素小人一致
- [ ] 附资产条目 JSON

## 四、你不需要关心的事（工程侧负责）

- 模型的加载、克隆、贴图替换、摆放、碰撞、动画——全部程序实现。
- 世界快照 schema、资产白名单的录入与校验。
- UI 布局、交互、后端。你的风格定义会被翻译成代码，不需要你写 CSS/JS。

## 五、接口边界（唯一的协作触点）

1. 你产出 → GLB/PNG 文件 + 资产条目 JSON + 风格色板。
2. 工程侧消费 → 经 `asset-catalog.json` 白名单加载（schema `echo-assets.v1`，硬校验）。
3. 风格变更 → 先改本文件的风格定义，工程侧同步 CSS/灯光参数；不要直接改已入库资产。
4. 争议裁决 → 以"文件能过验收清单"为准，不以口头描述为准。
