# EchoWorld 美术协作提示词（画面/风格负责人专用）

> 用法：本文件整体转发给负责画面风格的协作者（人或 AI 均可）。自包含，无需其他上下文。
> 工程侧联系人见文末"接口边界"。本文件版本：art-brief.v1（2026-08-03）

---

你负责一个 3D 智能体社交产品 **EchoWorld** 的全部视觉资产与美术风格。产品是"把现实中的相遇变成生活在 3D 世界里的智能体"：用户在低多边形咖啡厅/集市世界里走动，点击像素小人查看真实人物资料包。当前为 MVP 阶段。

**画风已最终确定（2026-08-03，不再变更）：低多边形（low-poly）+ 有脸的个性化人物 + 收藏手办质感。** 不做写实、不做二次元、不做体素。具体基调：

- **每个人都是独立的低多边形模型**：由生成管线产出（真人照片 → AI 三视图 → Blender 生成 GLB），**有五官**（低多边形简化的眼睛/鼻子/嘴，非写实贴图），核心目标是"看一眼能认出是谁"——这是产品解决脸盲问题的关键载体；
- **过渡说明**：硬件输入打通前，临时使用无脸占位模型（`character.faceless-prototype.v1`，同一几何按调色板换色）。占位模型不是方向，正式方向是有脸的 per-person 模型；
- **头身比 1:2.5~1:3 的 Q 版比例**（大头小身，盲盒/手办感），辨识度来自：五官特征 + 发型轮廓 + 服装配色 + 体型；
- **哑光材质**：roughness ≥ 0.7，禁止高光塑料感；纯色材质优先，贴图非必需；
- **微缩模型（diorama）场景**：咖啡厅/集市像一个可俯视的温暖沙盘，手工感；
- **灯光氛围**：暖色柔光 + 长软阴影，室内暖光基调；
- 设计心理目标：每个新人物 = 获得一个新手办，"世界逐渐摆满"是产品的核心视觉体验。

## 一、你要交付的 4 类资产

### 1. 人物模型（最高优先级，产品的核心载体）

**正式方向：每个真实的人对应一个独立的低多边形模型**，由生成管线自动产出：

```
真人照片（眼镜/手机拍摄，一张或多张）
  → AI 生成三视图（正面/侧面/背面）
  → AI 调用 Blender 按三视图生成 lowpoly GLB
  → 登记入资产白名单，部署到 three.js 世界
```

相遇的第一现场（展位、桌位、环境）走**同一条管线**建模；人与场景解耦——人是可动的 Agent 模型，场景是静态模块，两者只在世界快照中按坐标组合。

你（美术）在这个管线里的职责：

- **制定风格规范**：三视图生成 prompt 模板（姿势、构图、背景、风格词）、Blender 生成脚本的风格参数（头身比 1:2.5~3、五官的低多边形简化规则、面数预算、从照片提取调色板的规则）——管线产物必须长得像你定的风格；
- **交付 2-3 个手工精修的基准模型**：作为管线输出的质量锚点与回归基准（管线产物与基准模型并排渲染对比，差距过大即打回打磨）；
- **过渡期占位模型**：在硬件输入打通前，迭代现有无脸占位模型（同一几何按调色板换色）。

硬性技术契约（管线产物与手工模型都必须满足）：

- 格式：GLB，单个无骨骼刚性模型（**不需要骨骼、不需要动画**，移动/入座由程序做刚体变换）。
- 规格：身高 **1.65 米**（程序按米制摆放；Q 版指头身比例，世界中占位高度不变）；原点在**脚底中心**；面朝 **+Z 方向**；根节点命名 `ROOT_Character`（白名单条目有 `root_node` 字段，按条目读取；过渡期的无脸占位模型沿用 `ROOT_FacelessCharacter`）。
- 脸：**有五官**（低多边形简化的眼/鼻/嘴，非写实贴图），生成目标是"熟人看一眼能认出是谁"。
- **材质命名是硬接口**：模型必须拆出独立材质槽，材质名包含以下小写关键词——`jacket`、`hair`、`skin`、`pants`、`shoes`、`shirt`（程序按材质名换色/提取调色板）；可选增加 `eyes`（瞳色区分）。材质名不对 = 无法换色 = 返工。
- 面数预算：单个人物 ≤ 5k 三角面；贴图非必需，纯色材质优先；文件 ≤ 2MB。

### 2. 环境/场景模型

- 现有咖啡厅环境 GLB 的迭代版 + **新增"展位"场景模块**（黑客松/展会摊位：一张台子 + 背景板 + 可放 logo/贴图的位置，背景板预留 UV 区域供程序贴现场照片）。
- 格式：GLB，米制，原点在场景中心地面，面朝 +Z。
- 面数预算：整个咖啡厅环境 ≤ 100k 三角面；单个展位 ≤ 15k。
- 程序用**圆形阻挡体**做碰撞，不需要你导出碰撞壳，但桌椅等占位要符合直觉尺寸（桌高约 0.75m，通道宽 ≥ 1.2m）。

### 3. 人物头像（资料包面板用）

- 正方形 PNG，≥ 1024×1024，统一渲染规范：**由该人的低多边形模型渲染**（固定机位正面胸像、柔和顶光、纯色/渐变背景），保证头像与世界里的小人是同一个人。
- 过渡期：无脸占位模型统一渲染（现有 7 张 `chen-mo.png` 等可作起点迭代），管线打通后逐人替换为 per-person 渲染。

### 4. 视觉风格基调（style tile）

- 一页风格定义：主色板（含 hex）、辅色、材质质感（哑光/柔和阴影）、灯光氛围（暖色夕阳感 or 室内暖光）、字体建议。
- 工程侧会把色板落成 CSS 变量和 Three.js 灯光参数，你只出定义，不写代码。

## 二、硬性技术约定（违反即无法入库）

1. 一律 GLB（二进制 glTF），PBR 材质；不交付 .blend/.fbx/.obj 作为最终产物（源文件请自行保留）。
2. 米制单位；Y 轴向上；面朝 +Z。
3. 文件命名：全小写蛇形，带语义和日期，如 `echo_world_booth_template_20260810.glb`。
4. 每次交付附一行 JSON 资产条目（工程侧会录入白名单）：

```json
{
  "asset_id": "environment.booth-template.v1",
  "kind": "environment-module",
  "url": "models/modules/echo_world_booth_template_20260810.glb",
  "version": 1
}
```

5. **只增不改**：已入库的资产不改文件内容，迭代 = 新文件 + `version` +1 + 新 asset_id（v2）。旧版本可能正在被线上使用。

## 三、验收清单（交付前自查）

- [ ] GLB 在 https://gltf-viewer.donmccurdy.com/ 打开正常，比例、朝向正确
- [ ] 人物模型 6 个材质槽齐全且命名含规定关键词
- [ ] 文件大小：人物 ≤ 2MB，环境 ≤ 10MB（web 加载预算）
- [ ] 头像 PNG 正方形、风格统一、与 3D 调色板一致
- [ ] 附资产条目 JSON

## 四、你不需要关心的事（工程侧负责）

- 模型的加载、克隆、换色、摆放、碰撞、动画——全部程序实现。
- 世界快照 schema、资产白名单的录入与校验。
- UI 布局、交互、后端。你的风格定义会被翻译成代码，不需要你写 CSS/JS。

## 五、接口边界（唯一的协作触点）

1. 你产出 → GLB/PNG 文件 + 资产条目 JSON + 风格色板。
2. 工程侧消费 → 经 `asset-catalog.json` 白名单加载（schema `echo-assets.v1`，硬校验）。
3. 风格变更 → 先改风格定义页，工程侧同步 CSS/灯光参数；不要直接改已入库资产。
4. 争议裁决 → 以"文件能过验收清单"为准，不以口头描述为准。
