# EchoWorld 美术协作提示词（画面/风格负责人专用）

> 用法：本文件整体转发给负责画面风格的协作者（人或 AI 均可）。自包含，无需其他上下文。
> 工程侧联系人见文末"接口边界"。本文件版本：art-brief.v2（2026-08-03）

---

你负责一个 3D 智能体社交产品 **EchoWorld** 的全部视觉资产与美术风格。产品是"把现实中的相遇变成生活在 3D 世界里的智能体"：用户在体素（MC 风格）的市集/咖啡厅世界里走动，点击像素小人查看真实人物资料包。当前为 MVP 阶段。

**画风已最终确定（2026-08-03 第二次定稿）：MC 体素（voxel）+ AI 生成图片贴图。** 原"低多边形 + 有脸 per-person 模型"方向已废弃（生成成本与速度不满足现场群体场景）。具体基调：

- **每个人都是 MC 体素风格人物**：体素身体 + AI 根据真实照片生成的图片贴图（头部五面 + 身体 atlas），辨识度来自**面部特征贴图** + 发型轮廓 + 服装配色，核心目标是"看一眼能认出是谁"——这是产品解决脸盲问题的关键载体；
- **资料包内始终保留真实人脸照片**：小人负责"世界里有你"，真实脸负责"确认是你"，这是接受度策略的一部分；
- **世界是体素/低精度 3D**：市集（室外主场景，一条可扩展的街）、咖啡厅（街上一间室内小屋）、个人场域（AI 根据个人素材生成的特质空间，风格化、有隐喻，允许粗糙与超现实）；
- **微缩模型（diorama）沙盘感**：世界像一个可俯视的温暖手工沙盘；
- **灯光氛围**：暖色柔光 + 长软阴影，室内暖光基调；
- 设计心理目标：每个新人物 = 世界多一个居民，"世界逐渐热闹"是产品的核心视觉体验。

## 一、你要交付的 4 类资产

### 1. 人物模型（最高优先级，产品的核心载体）

**正式方向：每个真实的人对应一个 MC 体素人物 + AI 生成图片贴图**，由生成管线自动产出：

```
真人照片（眼镜/手机拍摄，一张或多张）
  → AI 生成图片贴图（头部五面 + 身体 atlas）
  → 体素 GLB 组装（固定体素身体 + 动态贴图）
  → 登记入资产白名单，部署到 three.js 世界
```

你（美术）在这个管线里的职责：

- **制定风格规范**：体素人物的头身比与体素分辨率、贴图生成 prompt 模板（从真实照片到像素化面部特征的转换规则：保留哪些辨识特征、如何简化）、从照片提取服装配色的规则——管线产物必须长得像你定的风格；
- **交付 2-3 个手工精修的基准人物**：作为管线输出的质量锚点与回归基准（管线产物与基准并排渲染对比，差距过大即打回打磨）；
- **过渡期占位人物**：管线打通前，迭代现有体素占位人物（固定身体 + 默认贴图）。

硬性技术契约（管线产物与手工模型都必须满足）：

- 格式：GLB，单个无骨骼刚性模型（**不需要骨骼、不需要动画**，移动/入座由程序做刚体变换）。
- 规格：身高 **1.65 米**（程序按米制摆放）；原点在**脚底中心**；面朝 **+Z 方向**；根节点命名 `ROOT_Character`（白名单条目有 `root_node` 字段，按条目读取）。
- **贴图槽位是硬接口**：头部五面贴图 + 身体 atlas 的槽位命名/UV 约定必须与前端体素实现（`CharacterVariants` voxel 方案）对齐；命名不符 = 无法贴图 = 返工。
- 辨识度验收：贴图完成后，熟人盲测"这是谁"命中率 ≥ 基准人物水平。
- 预算：单个人物 ≤ 5k 三角面；文件 ≤ 2MB。

### 2. 环境/场景模型

- **市集街道**（室外主场景）：一条可扩展的街 + **摊位模块**（一张台子 + 背景板 + 可放 logo/贴图的位置，背景板预留 UV 区域供程序贴现场照片）。
- **咖啡厅小屋**：现有咖啡厅场景作为市集街上的一间室内小屋接入（熟人社交定位）。
- **个人场域风格定义**：场域内容由 AI 根据个人素材生成（风格化、有隐喻，允许粗糙），你出**风格规则与边界**（基调词、禁区、与现实照片的衔接方式），不逐个手做。
- 格式：GLB，米制，原点在场景中心地面，面朝 +Z。
- 面数预算：街道整体 ≤ 100k 三角面；单个摊位/小屋 ≤ 15k。
- 程序用**圆形阻挡体**做碰撞，不需要你导出碰撞壳，但占位要符合直觉尺寸（桌高约 0.75m，通道宽 ≥ 1.2m）。

### 3. 人物头像（资料包面板用）

- 正方形 PNG，≥ 1024×1024，统一渲染规范：**由该人的体素模型渲染**（固定机位正面胸像、柔和顶光、纯色/渐变背景），保证头像与世界里的小人是同一个人。
- 过渡期：占位体素人物统一渲染，管线打通后逐人替换为 per-person 贴图版本。

### 4. 视觉风格基调（style tile）

- 一页风格定义：主色板（含 hex）、辅色、材质质感（哑光/柔和阴影）、灯光氛围（暖色夕阳感 or 室内暖光）、字体建议。
- 工程侧会把色板落成 CSS 变量和 Three.js 灯光参数，你只出定义，不写代码。

## 二、硬性技术约定（违反即无法入库）

1. 一律 GLB（二进制 glTF）；不交付 .blend/.fbx/.obj 作为最终产物（源文件请自行保留）。
2. 米制单位；Y 轴向上；面朝 +Z。
3. 文件命名：全小写蛇形，带语义和日期，如 `echo_world_booth_template_20260810.glb`。
4. 每次交付附一行 JSON 资产条目（工程侧会录入白名单）：

```json
{
  "asset_id": "environment.booth-template.v1",
  "kind": "environment-module",
  "url": "models/modules/echo_world_booth_template_20260810.glb",
  "version": 1
}
```

5. **只增不改**：已入库的资产不改文件内容，迭代 = 新文件 + `version` +1 + 新 asset_id（v2）。旧版本可能正在被线上使用。

## 三、验收清单（交付前自查）

- [ ] GLB 在 https://gltf-viewer.donmccurdy.com/ 打开正常，比例、朝向正确
- [ ] 人物模型贴图槽位齐全且命名与前端 voxel 实现一致
- [ ] 贴图辨识度：熟人盲测能认出是谁
- [ ] 文件大小：人物 ≤ 2MB，环境 ≤ 10MB（web 加载预算）
- [ ] 头像 PNG 正方形、风格统一、与 3D 形象一致
- [ ] 附资产条目 JSON

## 四、你不需要关心的事（工程侧负责）

- 模型的加载、克隆、贴图、摆放、碰撞、动画——全部程序实现。
- 世界快照 schema、资产白名单的录入与校验。
- UI 布局、交互、后端。你的风格定义会被翻译成代码，不需要你写 CSS/JS。

## 五、接口边界（唯一的协作触点）

1. 你产出 → GLB/PNG 文件 + 资产条目 JSON + 风格色板。
2. 工程侧消费 → 经 `asset-catalog.json` 白名单加载（schema `echo-assets.v1`，硬校验）。
3. 风格变更 → 先改风格定义页，工程侧同步 CSS/灯光参数；不要直接改已入库资产。
4. 争议裁决 → 以"文件能过验收清单"为准，不以口头描述为准。
