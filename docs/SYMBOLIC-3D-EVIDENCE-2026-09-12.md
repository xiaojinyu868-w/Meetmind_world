日期：2026-09-12。AI 辅助来源核验；本轮未安装运行以下项目，也未复现论文效果。不是“全网最新”排名。

## 四种路线不要混在一起

| 工作 | 已核实的表示与路径 | 对 MeetMind 有用的部分 | 没有得到证明的部分 |
| --- | --- | --- | --- |
| [SceneCraft，NeurIPS 2024](https://github.com/OrangeSodahub/SceneCraft) / [论文](https://arxiv.org/abs/2410.09049) | 布局、物体框/标签、相机 -> 语义与深度条件 -> 扩散指导 NeRF。编辑器导出 layout.json、cameras.json | 语义布局指导视觉生成；可作为外观路线对照 | 成品不等于可逐对象编程的 mesh/行为系统；编辑条件不等于事件持续状态。README要求场景训练至少两张GPU |
| [Holodeck，CVPR 2024](https://yueyang1996.github.io/holodeck/) / [仓库](https://github.com/allenai/Holodeck) | 文本 -> 房间、物体、关系约束 -> Objaverse 资产检索与布局优化 -> AI2-THOR/Unity 场景 | 将“使用需求”落实为布局与可检查约束，比只生成一张房间图更贴近空间任务 | 不是任意照片的精确重建；不保证每件资产都有完整动作；没有证明长期真人经历自动持续更新 |
| [The Scene Language，CVPR 2025 Highlight](https://ai.stanford.edu/~yzzhang/projects/scene-language/) / [仓库](https://github.com/zzyunzhi/scene-language) | 文本/图片 -> 程序（结构）、自然语言（语义类别）、嵌入（外观/身份）；分层函数对应部件，可控制与编辑 | 世界保留可解释的结构、部件与语义，而非只留一份最终外观 | 公开实现有 Mitsuba、Minecraft、层级 PLY；README 的3DGS仍“Coming soon”。4D对应关系不等于跨月生活记忆或多人决策 |
| [ProcFunc，2026-04-29预印本](https://arxiv.org/abs/2604.26943) / [仓库](https://github.com/princeton-vl/procfunc) / [Infinigen 2文档](https://infinigen.cs.princeton.edu/docs/latest/) | Blender Python函数式几何/材质生成、函数组合与参数分析、节点转Python和执行跟踪；Infinigen提供生成器 | 可组合的几何/材质接口；作者报告VLM编辑代码实验，值得作为资产编译接口参考 | 不是单独的文本到世界模型；Infinigen2为preview/alpha、物体类别和布局仍有限；未验证长期社交体验 |

官方仓库许可证核对：SceneCraft/Scene Language为MIT，Holodeck为Apache-2.0，ProcFunc为BSD-3-Clause；此处未引入任何代码或资产。模型权重、外部资产与具体版本需要单独核对，不能从代码许可证推断所有产物权利。

## 对“现在是否可以重新做”的判断

可以把技术探索目标提高到**可编辑、可检查、能保持身份的生成空间**。公开证据支持程序结构、语义与生成资产相结合的方向；尚不足以承诺任意材料输入后直接生成游戏大厂级人物、动作和完整世界。

不应把“三维几何由程序画出来”直接等同于前沿能力。当前 MeetMind 的受限 recipe 已证明参数到几何、稳定部件ID与增量编辑的路径，但表达能力主要是基础图元，复杂物件的形体、材质和动作还需提升。

已有关系/事件/访问框架与生成器作用不同：

~~~text
经过确认的现实材料与各自要求
  -> 可追溯的语义对象、关系与约束
  -> 模型提出结构/布局/外观变更
  -> 约束检查 + 人的选择
  -> 同一版本的2D/3D呈现
  -> 明确的现实行动与反馈
  -> 后续事件更新
~~~

这是建议的工程路线，不是上述论文已实现的组合。资产外观可以来自手工、程序化生成、mesh生成或其他渲染方式；权威事件、对象身份与选择不依赖某一种视觉模型。已有同意不能被下一次重绘覆盖。

## 下一步技术实验应验证什么

与 [共同空间切片](SHARED-SPACE-EXPERIMENT.md) 结合，先把多人真实约束、布局补丁与版本决策串起来。
在有真实模型可用后，与“每次整场重新生成”比较：

1. 修改一个明确要求，未受影响的对象及其已确认用途能否保持。
2. 输出方案中约束冲突能否被独立检查，并准确归因到具体需求。
3. 无法同时满足时能否返回冲突与候选妥协，而非视觉上掩盖问题。
4. 两个人是否知道自己接受的是哪个版本，现实反馈能否回到相同对象。
5. 导出、重开与更换渲染器后，语义状态是否仍一致。
6. 在同一任务的可操作2D平面与3D之间，是否减少误解和返工，而非仅增加停留时间。这个对照只检验呈现，
   上下文协助需要固定呈现、与手工整理相同材料的流程另作对照，不能把几个变化混成一个效果。

技术测量需记录模型/版本、输入、延迟、费用、无效输出、人工修正和失败案例；目前账户Arrearage仍未解决，不把人工场景称为AI实测。
